# 隔声试验数据交付复核工具

声学实验室向外部复核方交付隔声试验数据的网页工具：从上传的 SQLite 库中勾选试验、
剔除个别异常读数，沿对照/校准引用自动补齐所需记录，确认预览后下载 SQLite 子库。

## 运行

```bash
docker compose up --build
# 打开 http://localhost:8000
```

本地开发（Python 3.11+）：

```bash
pip install -r requirements-dev.txt
python3 scripts/make_sample_db.py sample.db   # 生成演示库
uvicorn app.main:app --reload
```

运行测试：`pytest`

## 数据库结构约定

上传的 SQLite 库需包含四张表（关键列名固定，其余列任意）：

| 表 | 关键列 | 说明 |
| --- | --- | --- |
| `groups` | `id`, `name` | 试验组 |
| `calibrations` | `id`, `device` | 校准记录 |
| `tests` | `id`, `group_id→groups`, `calibration_id→calibrations`(可空), `name` | 试验 |
| `readings` | `id`, `test_id→tests`, `calibration_id→calibrations`(可空), `control_reading_id→readings`(可空), `kind` | 读数；`control_reading_id` 为对照读数引用，允许跨组 |

## 交付规则

1. 交付所选试验中未被剔除的全部读数；
2. 沿对照引用（`control_reading_id`）与校准引用（`calibration_id`，读数级与试验级）
   补齐所需记录；对照读数允许跨组互引；
3. 跨到未勾选的组时，只带入沿引用找到的读数，以及这些读数所属的试验、
   试验所属的组（维持外键完整所必需）和引用到的校准记录；
4. 引用悬空（目标不存在）或指向已剔除读数时，预览页展示完整引用链并**阻止下载**；
5. **引用质量核查**：对交付范围内的每条 `measurement` 读数沿 `control_reading_id`
   逐跳核查，任一不通过即**阻止确认报告**（见下节）；
6. 子库建表语句复用源库 DDL 原文，主键、外键约束、索引原样保留，行按原主键写入，
   导出后执行 `PRAGMA foreign_key_check` 校验。

## 引用质量核查（对照链频点一致性）

声学实验员怀疑对照链把不同频点的读数混在一起。系统在「引用质量核查」页
（导航栏入口 `/quality`）对交付范围内的每条 `measurement` 读数，沿
`control_reading_id` 逐跳检查，识别以下问题并取沿链发现的**首个**问题：

| 问题类型 | 判定 |
| --- | --- |
| 频点冲突 | 链上相邻读数 `frequency_hz` 不一致 |
| 缺频点 | 链上任一读数 `frequency_hz` 为 NULL（停止继续追链） |
| 悬空 | `control_reading_id` 指向不存在的读数 |
| 成环 | 链回到已出现过的读数（含自引用） |
| 链末端非对照 | 追至引用为 NULL 的末端，其 `kind` 不是 `control` |
| 无对照 | `measurement` 读数没有 `control_reading_id` |

- 每条问题链展示从起始 measurement 出发的**完整引用链**（含跨组引用），
  并在出问题的一跳标注原因；问题**按受影响试验汇总**；
- 中途的 `control` 读数若仍带引用会继续追踪，仅链末端必须是 `control`；
- 仅 `measurement` 读数作为核查起点，被剔除的读数不纳入核查范围；
- 全部对照链通过、且引用解析无冲突时，才允许「确认报告并下载」；
  服务端在 `/download` 重新解析并复核，页面状态被绕过也会返回 409。

## 源库更换保护

上传时记录源库文件的 SHA-256 指纹。确认前若发现工作目录中的源库指纹变化
（文件被更换或篡改），一律拒绝重新确认并返回 409，预览/核查页显示告警横幅；
源库损坏为非 SQLite 时页面降级为阻止页。上一版已确认的子库文件保留在会话工作目录，
可通过「引用质量核查」页或 `/last-subset` 继续下载。同内容覆盖（指纹不变）不视为更换。

## 使用流程

1. **上传**：选择实验室导出的 SQLite 库（结构不符会给出具体缺失项）；
2. **选择**：按组勾选要交付的试验，可在所选试验下勾选要剔除的异常读数；
3. **预览**：查看交付汇总、跨组带入的读数及其引用链；若存在引用冲突，
   展示每条冲突的完整引用链，下载按钮禁用；
4. **引用质量核查**：查看对照链频点核查结论与按试验汇总的问题链；
5. **确认下载**：引用解析与质量核查全部通过后确认，下载 `*_subset.db`。
   下载前服务端重新解析、复核并校验源库指纹，任一不满足则返回 409 拒绝。

## 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DATA_DIR` | `./data`（容器内 `/data`） | 上传文件与子库的工作目录 |
| `MAX_UPLOAD_MB` | `200` | 上传大小上限 |

## 已知限制

- 会话保存在单进程内存中，重启后需重新上传；上传文件保留在 `DATA_DIR`，
  需运维定期清理（未实现自动清理）；
- 未做多用户隔离与鉴权，仅供实验室内网使用；
- 表名/关键列名固定，如实验室库结构不同需先适配（见 `app/core.py` 顶部约定）。
